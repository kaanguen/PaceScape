# Current-run and all-time tempo comparison

The PR ghost replays the measured speed trace of a fully completed treadmill effort, with average-speed fallback for older records without a trace. The selected measurement distance is either **400 m** or an arbitrary whole-metre distance entered in kilometres, for example 5 km or 10 km. It is independent of the selected visual lane circumference; the oval, anchor, start offset and XR rig are not recalibrated or moved by this feature.

## Ghost modes and workflow

The avatar is an independent ghost. Its pacing reference is separate from placement: it may follow the anchored oval or appear beside a calibrated treadmill position. There are exactly two pacing references:

| Ghost reference | Source |
| --- | --- |
| `FixedPace` (default) | The preset pace/speed slider, unchanged by live belt speed and current-run results |
| `AllTimePersonalBest` | The selected-distance PR trace, followed by longer stored PR sections; average pace for legacy records |

1. Install the ghost-only Android build, restart Control, and select **Ghost · voreingestelltes Tempo** or **Ghost · All-time PRs** under **Ghost einstellen**.
2. Set preset speed, lane and start position as before. For PR comparison choose 400 m or a custom kilometre distance. A distance change requires reset; mode changes pause without rewinding.
3. Place and track the ghost, then explicitly start/resume. It advances independently along the configured lane; neither zero belt speed nor missing BLE changes its target. Tracking loss, backgrounding and server loss still pause the session.
4. Connect the treadmill to measure the user's distance, time, laps and real PRs. These come only from belt samples, never ghost displacement or animation. Missing input cannot manufacture user progress. Current-run bests remain visible as user statistics but are not a ghost reference.
5. All-time mode uses the persisted distance record. When none exists, it retains the preset fallback or an explicitly enabled, labelled example. A new faster real PR updates the stored record; the active playback snapshot stays unchanged until reinitialized, and FixedPace is never overridden.

A measurement lap is a fixed block of the selected distance. Rolling best efforts can start between lap boundaries. The current selected distance is evaluated for that run; historical activities are not retained for retrospective evaluation of other distances. No side-by-side behavior, head-following position or new user-relative placement/calibration was added. The ghost keeps the existing independent lane path and configured starting offset.

## Measurement definition

- The data source is the reported FTMS belt speed, not avatar travel, animated gait, configured target pace or device total-distance counter. The preceding known sample is held across each frame interval; constant-speed distance boundaries are interpolated. Thus results describe this sampled belt telemetry, not certified physical running speed or stadium calibration.
- Fastest continuous windows are evaluated when either end crosses a speed-change boundary, including interior crossings. Coalescing equal speeds avoids retaining per-frame points; old points outside the relevant window are pruned. Exactness refers to this piecewise constant observed trace, not unknown changes between BLE notifications.
- Fresh 0 km/h is a valid stopped interval and contributes time. Paused sessions, missing/invalid/stale speed, source disconnects, unavailable placement, backgrounding and frame gaps longer than the existing two-second freshness policy break continuity. No effort spans an unknown interval. A partially measured fixed lap is flagged invalid until its next boundary; subsequent complete laps can qualify. Previously completed records survive interruptions.
- This is inspired by [Strava running Best Efforts](https://support.strava.com/en-us/articles/15401661-how-do-best-efforts-work-for-running-on-strava): the fastest completed distance within a run and elapsed time including known stops. It is not a Strava API integration or a claim to reproduce their proprietary GPS processing. Strava's manually entered official-race **All-Time PRs** are distinct from their automatically calculated Best Efforts; this app's displayed PRs are explicitly treadmill-derived.
- User reset/tracking teardown begins new current-run measurements. All-time bests survive. Changing avatar mode preserves completed current-run measurements; pausing still invalidates an incomplete measurement block. No peak instantaneous speed or incomplete projected finish time becomes a record.

## Real records and demonstrations

Real records are stored on this device at `Application.persistentDataPath/pacescape-treadmill-personal-bests.json`, keyed by integer metres, with elapsed seconds and a UTC timestamp. They load once for the scene, validate version/data, and fall back to a `.bak` file if needed. Faster or first genuine efforts update memory immediately. Main-thread JSON snapshots are written by one background task through a temporary file and replacement/backup. Writes are coalesced and normally at most once per five seconds; pending writes/errors appear in telemetry. Backgrounding requests a flush. Avoid terminating the app while saving is pending; an abrupt OS kill can lose the newest not-yet-written improvement.

Storage is local to this app installation and has no account/user separation or cloud sync. Uninstalling/clearing app storage can remove records. Engineering limits are 1–1,000,000 whole metres per distance, 1,024 stored distances, 1 MiB input files, and 200,000 retained speed-change points per continuous trace. Capacity failures do not manufacture records.

Fictional examples are separate constants: 400 m in 120 s, 5 km in 1,500 s, and 10 km in 3,300 s. **Gekennzeichnete Beispiel-PRs als Ersatz verwenden** is off by default. When enabled, an example may pace the all-time partner only if that distance has no measured PR. The badge says **BEISPIEL · fiktiver PR**. Examples never populate the real record table/file; the first real result wins even if slower than the example. FixedPace mode always uses the preset, even when a real current-run best or all-time record exists.

## Code and protocol

- `Assets/Scripts/Performance/DistancePerformance.cs`: fixed-distance blocks and bounded lap history.
- `RollingDistanceBest.cs`: continuous-window search with interpolated boundaries and retained session best.
- `PersonalBestBook.cs`: versioned, exact-distance measured records and strictly faster updates.
- `RunnerPerformance.cs`: scene-owned sampling, target selection, storage and telemetry. It binds to the runtime client, tracker and treadmill input without serialized scene changes.
- `TagTracker` / `ServerTestScene`: apply the selected comparison target through existing `RunningTrackMotion`; explicit reset clears session statistics. Preview has no real BLE measurements, but supports demonstration targets.
- State advertises `comparisonControlVersion: 1`, `activeRunnerPace`, and a `performance` object. `runner.comparison` requires `{ "comparisonDistanceMetres": 5000, "useDemoRecords": false }`. `runner.mode` accepts exactly `FixedPace` and `AllTimePersonalBest`. State additionally advertises `ghostControlVersion: 1`; older mirror/current-run builds must be updated before the ghost controls are enabled.
- Control's simulator advertises the capability and can exercise configuration/demo display, but never creates measured PRs or simulates real BLE by itself.

## Dynamic PR replay — 2026-11-06

The selected comparison distance remains the user's fixed-lap and rolling-record measurement distance, and is the ghost's initial reference. No automatic multi-distance record collection is added. To obtain a longer-distance PR, measure that distance in a separate configured run. Reference progression uses the smallest strictly longer measured record available, not a fixed list of kilometre milestones. Missing intermediate distances are skipped; fictitious examples never create longer measured references.

New real records include relative time/distance boundaries for their winning rolling window, clipped to exactly its beginning and end. Equal-speed intervals are coalesced; stationary intervals remain. No trace bridges a measurement interruption. Only a genuinely faster result replaces an existing record; an equal result does not retrofit an old record with a trace. Older time-only JSON remains valid and plays at average pace. The version-1 book retains optional trace fields. Stored traces share a 32,000-point budget; beyond it the best time remains stored without replay data. The validated file-size limit is now 8 MiB. The detailed trace is omitted from WebSocket telemetry.

`GhostReplay` snapshots the measured record book when playback starts (or is reinitialized after a mode/fallback change). New bests cannot change the active opponent during that replay. Reset selects a fresh snapshot on the next start. Pause/resume retains playback time; a mode change preserves physical travelled distance and seeks the newly selected reference at that distance. Start offset and lane circumference never affect reference milestones.

At the end of a reference, enter the next longer record at the same absolute travelled distance. For example, at 5 km enter the 10-km trace at its first arrival at 5 km, including a stationary interval beginning there. Its earlier 0–5 km is not replayed. Each subsequent reference is selected similarly. If it has no trace, use that record's average speed until its distance boundary. If there is no longer record, retain the final segment speed indefinitely. No positional jump or restart occurs. A fallback preset/example also progresses to a longer measured reference when available, otherwise retains its speed. Without a measured trace, there is no invented historical speed variation.

Reference transitions can change speed immediately. Recorded displacement integrates every crossed boundary exactly; the existing 0.35-second response smooths animation only during replay so it cannot change the recorded finish time. FixedPace keeps its existing physical speed smoothing. The result after a reference switch is a composite opponent, not one historical run or a certified PR effort. Existing foreground/head/anchor/server pause gates remain active. No user-relative AR positioning is added.

Performance telemetry advertises `ghostReplayVersion: 1`, `ghostReferenceDistanceMetres`, `ghostPlayback` (`NotStarted`, `RecordedTrace`, `RecordAverage`, `Fallback`, `HoldingSpeed`), `ghostReferenceAchievedUtc`, and `ghostDistanceMetres`. The selected `comparisonDistanceMetres` does not change on automatic reference switches. `hasProgressComparison` gates `userLeadMetres`: comparison starts with the first fresh measurement and is suppressed after any subsequent measurement interruption until reset. It is sampled belt-distance comparison, not physical AR proximity. Ghost speed remains independent of live belt speed. A new full device build is required.

## Treadmill-relative presentation — current scope, 2026-11-06

This supersedes the earlier placement-only scope: the user authorized the same independent ghost to appear beside their fixed treadmill position. It does not add a pacing mode or make the ghost adopt live belt speed. In Control, open **Konfiguration > Ghost einstellen > Ghost-Darstellung**, choose **Stadion** or **Laufband**, and apply while Ready. The selector keeps the side offset and visibility distance reported by the app. After exactly one marker is placed and tracked, stand at the intended treadmill position and explicitly calibrate. The floor point beneath the head is stored in anchor-local coordinates. The nearest point on the selected lane centerline defines zero relative gap. The lane determines heading, independently of the user's gaze. Relative mode uses one marker and requires calibration plus fresh belt data for start/resume. The original track presentation remains the default and does not acquire these input requirements.

The floor-local pose is sampled along the selected lane at `nearestLaneMetres + ghostProgress - userProgress - startOffset`. The lane tangent sets the heading through bends. Progress uses the established first-fresh-measurement comparison origin; the existing configured start offset is retained. In relative mode dashboard `userLeadMetres` includes this offset so the displayed lead and longitudinal position agree. Ghost reference playback/gait remain independent of user speed: overtaking changes relative position only, without turning the runner or reversing its animation. The lane coordinate wraps around the oval. The signed gap used for visibility is unwrapped. This means relative physical movement and animated leg velocity have different meanings, as with a runner being overtaken.

The signed side offset is retained on the wire for compatibility. The selected lane centerline determines the lateral position. Visibility defaults to 10 m in either longitudinal direction and is configurable from 1–100 m. These are editable display/engineering choices, not training prescriptions. Per the user's choice, a gap beyond the configured limit hides only the runner renderer; logical progress continues. Renderers are restored within range without changing independent progress. Original disabled renderer flags are preserved. Existing head/anchor/content gates still apply. Unknown measurement gaps suppress relative placement until reset rather than estimating missing user motion. Pause freezes the last presented pose; after an interrupted measurement, resuming requires reset for a new continuous relative comparison. Stop/retry/new anchors discard calibration. Display settings/calibration are not persisted across app launches.

Tracking clients advertise `ghostPresentationVersion: 1` plus `ghostPresentation` (mode, sideOffsetMetres, visibilityDistanceMetres, calibrated, visible, status). `runner.presentation` and `runner.calibrate` are validated in Unity and capability-gated by Control. The marker-free server scene does not advertise physical calibration. The isolated Editor preview provides a labelled synthetic user speed slider, optional blue stationary user marker in overview, and first-person yaw/pitch controls. No synthetic measurements enter the real record book. Close the preview before running shared-resource cleanup tests, since it legitimately owns one shared track resource while open.
